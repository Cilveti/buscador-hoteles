## Decisiones

- Mantener `gpt-5.6-sol` high como juez fijo para comparabilidad.
- Decisión posterior: GPT-6 Sol high pasa a ser el juez fijo para campañas nuevas. Los resultados históricos conservan GPT-5.6 Sol y no se reetiquetan; los scores entre generaciones no se comparan como si tuvieran la misma calibración.
- No promover todavía GPT-6 Luna como candidato por defecto: ofrece una mejora grande de coste/latencia, pero no supera la fiabilidad de 5.6 en el caso complejo de estado y URL.
- No lanzar candidatos hasta que la suite general y el preflight real de los cuatro perfiles simultáneos sean verdes.
- Todos los casos usan `timeoutSeconds: 2700`, exactamente cuatro repeticiones y concurrencia cuatro.
- La parada segura es crear `.agent-evals/overnight-20260922/pause` y esperar al fin del caso; no matar worker/Chrome salvo limpieza explícita posterior.
- El primer plan compara EN/ES y proceso base/checklist de evidencia sobre tres tareas. No usa una exhortación genérica a ser exhaustivo, ya refutada por evidencia previa.
- No hay baseline legacy histórico: el producto nació ya hexagonal y sus fuentes permanecen iguales entre snapshots. La comparación futura usará dos entregas reales de `advanced-filters` con mismo origen y gates verdes como proxies explícitos, no una deuda sintética ni un supuesto historial.
- No modificar prompt, packet ni dossier del juez durante la campaña activa: el A/B de eficiencia se hará después sobre paquetes congelados y un golden separado por linaje.
- El prompt del juez se ha corregido para campañas futuras, no para las ya activas: un test entregado por el candidato que falla por una aserción reproducible bloquea `pass`, distinguiendo test incorrecto de bug funcional. Fases 2 y 3 congelan el nuevo hash `49ac1452…`; la fase 1 conserva el juez anterior para comparabilidad.
- No ejecutar un brazo con subagentes hasta conservar un resumen durable de rollouts padre/hijo; el stream JSON público no ofrece cobertura suficiente.
- El A/B de subagentes cambia una sola sección de proceso: control obliga a trabajar en raíz; tratamiento pide exactamente dos especialistas con archivos disjuntos, navegador y verificación final exclusivos de la raíz y espera explícita. Ambos mantienen el mismo modelo, tarea, baseline, skills, checks, aceptación y juez.
- Los brazos Gemini/Muse mantienen `judgePacketMode=full` para que el cambio sea modelo/arnés, no juez. El packet compacto se validará por replay del golden antes de mezclarse con comparaciones de candidatos.
- Usar campañas finitas y reanudables; detener nuevas salidas ante error de infraestructura, poco disco o plazo, sin ocultar intentos fallidos.
- Conservar como control `processSkill` completo; cualquier variante sin él será explícita, no el nuevo valor por defecto.

## Errores y correcciones

- No repetir comparaciones causales entre repositorios o protocolos distintos. Congelar baseline, especificación, skills, checks y dossier y cambiar una sola variable intencional.
- No confiar en un Chrome externo sin perfil protegido. Cada lanzamiento debe validar el sentinel privado y usar puerto/perfil asignados.
- No autoreintentar contextos rotos ni ocultar costes/tiempos no disponibles.
- No asumir que una operación de revalidación documentada sobrevive a la política de retención: reconstruir desde refs/commits retenidos y congelar metadatos mínimos a nivel de campaña. Eliminar el packet no debe eliminar la capacidad de repetir tests del candidato.
- El primer intento de sonda 4-way usó por error la variable reservada de zsh `status`; el shell terminó antes de conservar workers. Se comprobó que no quedaban procesos y se repitió como `v2`, completamente verde. Usar `exit_code` en zsh.
- Los probes iniciales usaron el CLI incluido en ChatGPT 0.155.0, pero el runner resolvía `codex` del PATH 0.149.1. Dos campañas fallaron antes de trabajo útil con «model is not supported». El arnés ahora resuelve `EVAL_CODEX_BIN` primero, después el CLI de ChatGPT en macOS y por último PATH; no volver a validar un modelo con un binario distinto del que registra el manifiesto.
- El workflow local aún llama a `codex` del PATH sin la resolución nueva del laboratorio. El primer run GPT-6 Luna del 23/09 falló en investigación porque el CLI global 0.149.1 recibió HTTP 400 «model is not supported». Repetir con el CLI de ChatGPT 0.155.0-alpha.2.6 antepuesto sólo al PATH de ese comando completó el workflow; no tratar el fallo inicial como defecto de Luna ni actualizar el CLI global sin necesidad.
- La primera integración formal se paró en el preflight del candidato: `personalSkillOverride` intentó listar `.codex/skills` bajo el sandbox que correctamente deniega esa ruta. El manejo explícito de EPERM/EACCES permite que el test funcione sin abrir el directorio ni relajar el aislamiento; la repetición pasó todos los controles y lanzó Luna. Conservar la tentativa fallida como error de infraestructura.
